🎯 Offertio

DACH-fokussierte Quoting & Invoicing SaaS für Handwerksbetriebe und kleine Serviceunternehmen

Zusammenfassung des Repositories für Claude AI

📋 Überblick

Offertio ist eine moderne SaaS-Anwendung, die es Handwerksbetrieben und kleinen Serviceunternehmen in Deutschland, Österreich und der Schweiz ermöglicht, professionelle Angebote und Rechnungen schnell und einfach zu erstellen, zu verwalten und zu versenden.

Die Lösung konzentriert sich auf Benutzerfreundlichkeit, mobile-first Design, und lokale Compliance (DACH-spezifische Anforderungen wie Schweizer QR-Rechnungen und deutsche ZUGFeRD e-Invoices).

Kernversprechen: Schnell onboarden → Sofort Angebote/Rechnungen erstellen → Professionelle PDFs versenden → Dokumenthistorie pro Kunde verwalten

🏗️ Core Architektur

Anfrage-Flow

  1. Public Traffic landet auf / (Marketing-Seite)
  2. Benutzer authentifizieren sich via /login
  3. src/middleware.ts enforced Supabase Sessions
  4. Benutzer müssen Onboarding abschließen
  5. Geschützte Routes ermöglichen Dokumenterstellung, PDF-Generierung und Versand
  6. API Endpoints erzwingen Origin-Checks, Auth-Checks, Payload-Limits und Rate Limits

Sicherheitsebenen

  • Browser & Transport: CSP mit Nonce, strenge Response Headers, Frame Denial
  • Request Validation: Origin-Checks, Payload Size Limits, Input Normalisierung
  • Abuse Controls: Upstash Rate Limiting, In-Memory Fallback für Dev
  • Data Access: Row-Level Security (RLS), Service-Role Client Isolation, HMAC-Validierung

📊 Dokumenten-Workflow

Der zentrale Product-Workflow folgt diesem Pattern:

  1. Erstellung: Benutzer wählt "Offerte" oder "Rechnung"
  2. Erfassung: Eingabe von Kundendaten, Positionen, Preisen
  3. Validierung: Client-seitige Vorschau, Server-seitige Limit-Checks
  4. PDF-Generierung: React-PDF-Component mit Branding & Logos
  5. Post-Processing:
    • Schweizer Rechnungen: QR-Code-Embedding
    • Deutsche Rechnungen: ZUGFeRD XML-Embedding
  6. Versand/Export: Email via Resend oder Download als PDF
  7. Persistierung: Dokumentzähler inkrementieren (Free-Plan Limit), State speichern

Besonderheit: Entwürfe werden Client-seitig persistent gemacht für UX-Kontinuität.

🌍 DACH-Spezifische Logik

Eine der wichtigsten Designentscheidungen ist die src/lib/dach.ts Abstraktion, die Land-spezifische Anforderungen zentralisiert:

Land Besonderheiten Spezifische Features
Schweiz (CH) QR-Rechnungen, SEPA-Zahlungen QR-Code-Generierung in Rechnungen
Deutschland (DE) Extensive e-Invoice Anforderungen ZUGFeRD XML-Embedding in PDFs
Österreich (AT) EU-Standard E-Invoicing ZUGFeRD XML-Support (optional)

Die DACH-Logik umfasst auch:

  • Land-spezifische MwSt. Labels und Sätze
  • Erforderliche Steuer- und Firmenfelder pro Land
  • Postleitzahl-Länge-Validierung
  • Anforderungen für Leistungsdatum

  • Nonce-basiertes CSP (Content Security Policy)

  • Frame-Denial (X-Frame-Options)

Request Validation

  • Origin-Validierung für sensitive APIs
  • Payload-Size-Limits
  • Input-Normalisierung mit Zod
  • Sichere Document IDs und Base64 Guards

Authentifizierung & Authorization

  • Supabase Auth mit Sessions
  • Row-Level Security (RLS) in PostgreSQL
  • Service-Role Client nur in Server-Code

Abuse Prevention

  • Upstash-basiertes Rate Limiting in Production
  • In-Memory Fallback für Local Development
  • HMAC-Validierung für Lemon Squeezy Webhooks

💪 Architektur-Stärken

  • Klare Route-Separation: Public → Protected → API ist sehr sauber
  • Zentralisierte DACH-Logik: Keine verstreu Compliance-Regeln
  • Migration-backed Schema: Versionierte SQL Migrations
  • Starke Sicherheit: Gut für ein Early-Stage SaaS
  • Gute Client-Separation: Browser, Server, Admin Supabase Clients
  • Optionale Integrationen: Services sind graceful fallback

📝 Bekannte Architektur-Grenzen

  • Kein Browser-Level E2E: Noch keine umfassende Playwright Suite (Foundation gelegt)
  • Premium Flows: Mehrere Flows hängen von externen Service-Konfiguration ab
  • Client-Side State: Editor-State nutzt Client-seitige Draft-Persistence für UX

Bewertung: Dies sind normale Limitierungen für ein Early-Stage Produkt und sollten mit Wachstum adressiert werden.

🎯 Key Features – Tiefere Einblicke

Onboarding Flow

Der Onboarding-Flow ist bewusst kurz gestaltet:

  1. Benutzer authentifiziert sich
  2. Grunddaten (Land, Firmennname, Steuernummer) erfassen
  3. Logo hochladen (optional)
  4. Zu Dashboard weiterleiten
  5. Compliance-Check: Benutzer mit unvollständigen Profilen werden zu Einstellungen umgeleitet

Free vs. Paid Plans

  • Free Plan: Limitierter Dokumentenzähler (z.B. 5 Dokumente/Monat)
  • Paid Plans: Unbegrenzte Dokumente, erweiterte Features
  • Enforcement: Server-seitig via dokument_counter Table
  • Checkout: Lemon Squeezy Integration für Zahlungen

Logo Upload & Branding

  • Logos werden in Supabase Storage gepuffert
  • RLS-Policies schützen gegen Unbefugte Zugriffe
  • PDFs rendern Logos in Dokumenten-Header

💰 Geschäftsmodell & Monetisierung

  • Free Plan: Limited monthly documents, basic features
  • Pro Plan: Unlimited documents, advanced templates, priority support
  • Checkout Flow: Lemon Squeezy-powered subscriptions
  • Webhook Validation: HMAC-signed webhook validation von Lemon Squeezy
  • Analytics: GA4, Meta Pixel optional für Conversion Tracking
